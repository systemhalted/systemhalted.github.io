In the [[/2025/12/16/basic-programming-lang/][previous post]], I followed the values through a small BASIC program. Following a program also means knowing which statement runs next. In GW-BASIC, =GOTO= lets us change that by sending execution to a numbered line.[fn:goto]

Here is a program that asks for a number between 1 and 10, inclusive. It keeps asking until the number is within that range.

#+begin_src basic
10 INPUT "Enter a number (1-10)"; N
20 IF N < 1 THEN GOTO 90
30 IF N > 10 THEN GOTO 90
40 PRINT "OK"
50 GOTO 110
90 PRINT "Invalid. Try again."
100 GOTO 10
110 END
#+end_src

This is still a small, readable program. Enter =12=, and line 30 sends execution to line 90. The program prints the error message, then line 100 sends it back to the input prompt. Enter =5=, and it reaches line 40, prints =OK=, then jumps to =END=.

The jumps have specific jobs. One path handles invalid input and retries. The other skips that error handling when the input is valid. We can establish both by following the line numbers.

Now suppose we want to print the accepted number before finishing. We might add:

#+begin_src basic
105 PRINT "Accepted:"; N
#+end_src

That statement will never run. After valid input, line 50 jumps directly to line 110. After invalid input, line 100 jumps back to line 10. Neither path reaches the new statement.

We could fix this by putting it at line 45 or changing the target of the jump at line 50. The edit is small, but making it correctly requires checking how the surrounding branches reach that part of the program.

GW-BASIC also provides =WHILE= and =WEND=, which let us express the retry as a loop.[fn:while]

#+begin_src basic
10 INPUT "Enter a number (1-10)"; N
20 WHILE N < 1 OR N > 10
30   PRINT "Invalid. Try again."
40   INPUT "Enter a number (1-10)"; N
50 WEND
60 PRINT "OK"
70 END
#+end_src

This preserves the original program's prompts and results. Both versions accept values from =1= through =10=, including a value such as =2.5=. They check a numeric range; neither requires a whole number.

At line 20, an out-of-range value causes the loop body to run. The program reports the problem and asks again. =WEND= returns to the condition for another check. Once the value is within range, execution continues at line 60.[fn:while]

The condition and the code it controls are now together. We can see where the retry begins, what it repeats, and where execution continues when validation succeeds.

To print the accepted number after =OK=, we can add =65 PRINT "Accepted:"; N=. It follows the completed validation loop without requiring a change to any branch target.

The =INPUT= statement appears twice in this version. I would accept that small amount of duplication here because the retry is easier to recognize and the work after validation is easier to extend.

There are useful applications of =goto= in other contexts. The Linux kernel's C coding guidance recommends it when several exit paths need shared cleanup, using a descriptive label such as =out_free_buffer=. That can avoid duplicating cleanup across several returns.[fn:cleanup]

For this BASIC program, I would use the loop. Someone adding work after validation can place it after =WEND= and see how execution reaches it.
