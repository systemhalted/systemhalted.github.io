In [[/2025/11/28/associativity-identity-folding/][Part 2]], we saw that adding =1.0= to =1e16= did not change the result. Here we will measure the spacing between values a =double= can store.

The distance between adjacent =double= values depends on their magnitude. We call this distance the /spacing/. At some magnitudes, the spacing is a small fraction of one. At others, it exceeds one.

We will start with machine epsilon, which measures the spacing just above =1.0=. Then we will use =Math.ulp= to examine other values. This will explain how spacing affects addition and what it tells us about comparisons.

** Machine epsilon at 1.0
:PROPERTIES:
:CUSTOM_ID: machine-epsilon-and-the-first-rung-above-1.0
:END:
In this post, /machine epsilon/ means the distance from =1.0= to the next larger =double=.

For a finite input, =Math.nextUp= returns the next value toward positive infinity.[fn:next-value] We can use it to measure this distance:

#+begin_src java
double next = Math.nextUp(1.0);
double epsilon = next - 1.0;

System.out.println(next);    // 1.0000000000000002
System.out.println(epsilon); // 2.220446049250313E-16
#+end_src

The value of =epsilon= is exactly =2^-52=. The decimal output identifies that binary value.

Some references use /machine epsilon/ to mean half this value, =2^-53=.[fn:epsilon-term] Check which definition a reference uses before applying its formulas.

Our definition measures the gap between two stored values. Whether an addition changes a result also depends on rounding.

** Measuring spacing with Math.ulp
:PROPERTIES:
:CUSTOM_ID: how-spacing-grows-with-magnitude
:END:
A /unit in the last place/, or ULP, measures the spacing at a particular value. Java provides =Math.ulp= to obtain it.[fn:ulp]

For the positive values in this table, the ULP is the distance to the next larger =double=:

| Value | =Math.ulp(value)= |
|-------+-------------------|
| =1.0= | =2.220446049250313E-16= |
| =10.0= | =1.7763568394002505E-15= |
| =1e8= | =1.4901161193847656E-8= |
| =1e16= | =2.0= |

The same input with a negative sign gives the same ULP. For example, =Math.ulp(-1e16)= also returns =2.0=.

At =1e16=, adjacent values are two units apart. We can see how this affects addition:

#+begin_src java
double value = 1e16;

System.out.println(value + 1.0);        // 1.0E16
System.out.println(value + 1.5);        // 1.0000000000000002E16
System.out.println(Math.nextUp(value)); // 1.0000000000000002E16
#+end_src

The adjacent values here are =10000000000000000= and =10000000000000002=. The exact sum of =value + 1.0= lies halfway between them.

For these additions, Java selects the nearest representable result. When two results are equally near, it uses the /round ties to even/ rule.[fn:rounding]

The /significand/ contains a number's significant binary digits. In a tie, Java selects the result whose last significand bit is zero. For =value + 1.0=, that result is the lower value.

For =value + 1.5=, the upper value is nearer. Java therefore rounds the sum upward. An increment smaller than one ULP can change the result.

** Why spacing changes at powers of two
:PROPERTIES:
:CUSTOM_ID: powers-of-two-where-spacing-jumps
:END:
A normal =double= has 53 bits of significand precision. It stores 52 of these bits explicitly. The leading bit is always =1=, so the format leaves it implicit.[fn:representation]

The exponent specifies the power of two used to multiply the significand. Within each range from one power of two to the next, the exponent remains constant.

For positive normal values in the range =2^e <= x < 2^(e+1)=, the spacing is =2^(e-52)=. Here, =e= is the binary exponent.

From =1.0= up to, but excluding, =2.0=, the spacing is =2^-52=. From =2.0= up to, but excluding, =4.0=, it is =2^-51=.

At a boundary, the gap below the value can differ from the gap above it:

#+begin_src java
double gapBelow = 1.0 - Math.nextDown(1.0);
double gapAbove = Math.nextUp(1.0) - 1.0;

System.out.println(gapBelow); // 1.1102230246251565E-16
System.out.println(gapAbove); // 2.220446049250313E-16
#+end_src

The gap below =1.0= is half the gap above it. This is why the definition of machine epsilon specifies the direction from =1.0=.

The smallest normal value needs separate treatment. The spacing does not double at that boundary.

** Subnormal values near zero
:PROPERTIES:
:CUSTOM_ID: near-zero-subnormals-exist-and-they-are-weird
:END:
=Double.MIN_NORMAL= is the smallest positive normal =double=. Its exact value is =2^-1022=.[fn:limits]

Values with nonzero magnitude below this limit are called /subnormal/. They extend the representable range toward zero.

Subnormal values have constant spacing: =2^-1074=. This is also the value of =Double.MIN_VALUE=, the smallest positive =double=.[fn:limits]

#+begin_src java
System.out.println(Double.MIN_NORMAL);
// 2.2250738585072014E-308

System.out.println(Double.MIN_VALUE);
// 4.9E-324

System.out.println(Math.ulp(0.0));
// 4.9E-324

System.out.println(Math.ulp(Double.MIN_NORMAL));
// 4.9E-324

System.out.println(Math.ulp(2.0 * Double.MIN_NORMAL));
// 9.9E-324
#+end_src

The first normal range uses the same spacing as the subnormal values. The spacing doubles at =2.0 * Double.MIN_NORMAL=.

Subnormal values do not have the implicit leading =1= used by normal values. As their magnitude decreases, fewer significant binary digits remain. Their fixed spacing becomes a larger fraction of the value, so their relative precision decreases.

This support for subnormal results provides /gradual underflow/. A calculation can produce values below the normal range before its result becomes too small and rounds to zero.[fn:rounding]

** What spacing tells us about comparisons
:PROPERTIES:
:CUSTOM_ID: why-equality-checks-on-doubles-are-dicey
:END:
Spacing describes which values a =double= can store. A comparison tolerance specifies how much difference an application accepts.

For finite values, =a == b= tests exact numerical equality. Use it when exact equality is the requirement. If two calculations can differ because of rounding, decide how much difference is acceptable before writing the comparison.

An /absolute tolerance/ sets a maximum difference in the same units as the values. For example, a requirement that permits a difference of =0.01= metres gives an absolute tolerance of =0.01= metres.

A /relative tolerance/ scales the permitted difference with the magnitude of the values. An absolute tolerance can also be needed for values near zero.

Choose these tolerances from the required accuracy, the units and the uncertainty in the input. Account for errors introduced by the calculation. Machine epsilon alone does not determine an acceptable tolerance, and one ULP does not bound the error of a complete calculation.
